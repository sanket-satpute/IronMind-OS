# V2.9 Sprint 11F.2B.3 Implementation Audit — Evidence Discovery

## 1. Discovery Architecture
**Planned**: A domain-level `EvidenceDiscovery` component was to be created in `com.sanket_satpute_20.ironmind.domain.engine` to coordinate bounded queries across `EventRepository`, `ObservationRepository`, and `ReflectionRepository`. It would own explicit parameters such as `userId`, time range bounds, limit, ordering, and cross-source deduplication and formatting into `EvidenceReference` objects.

## 2. Order Direction
**BLOCKED — Contract Ambiguity**:
The prompt instructed: *"If the contract defines only timestamp direction and leaves sourceId/sourceType direction ambiguous: STOP. Do not guess. Create an implementation audit describing the exact ambiguity. Do not silently choose ascending or descending secondary keys."*

The permanent contracts (`DATA_CONTRACT.md`, `SYSTEM_ARCHITECTURE.md`, `AI_BEHAVIOR_CONTRACT.md`) define that ordering is based on `TIMESTAMP_ASC` or `TIMESTAMP_DESC`, and that collisions are resolved using `timestamp` → `sourceId` → `sourceType`. However, the documentation **fails to specify the direction of the secondary and tertiary keys.**

Specifically, if the primary order is `TIMESTAMP_DESC`, it is completely ambiguous whether the tie-breakers:
1. Revert to standard ascending order (e.g., `sourceId` A→Z, and `EVENT < OBSERVATION < REFLECTION`).
2. Mirror the primary descending order (e.g., `sourceId` Z→A, and `REFLECTION < OBSERVATION < EVENT`).

Without an explicit contract defining the directionality of the tie-breaking components in both `ASC` and `DESC` scenarios, it is impossible to implement a deterministic global limit correctly across multiple sources without inventing semantics.

## 3. Global-Limit Strategy
**Planned**: The implementation would enforce `limit = N` by fetching exactly `N` items from each authorized source bounded by the time window, merging the candidates into a combined collection, sorting them using the canonical cross-source comparator, deduplicating using `(sourceType, sourceId)`, and returning the top `N` results.

## 4. Other Contract Assurances
- **Source Scope**: Empty `sourceScope` list would correctly short-circuit and yield zero repository calls.
- **Filters**: Observation and Event filters were verified to align with the repaired contracts.
- **Privacy**: No raw payloads would be exported from the domain boundary.
- **Failures**: Real repository exceptions would propagate naturally without being swallowed or returning incomplete lists.

---

## FINAL GATE
**BLOCKED — ORDER DIRECTION AMBIGUITY**

Implementation is aborted because the order direction of the secondary (`sourceId`) and tertiary (`sourceType`) tie-breaker keys is undefined in the permanent contract. 

An explicit policy decision is required: does `sourceId` / `sourceType` direction strictly mirror the primary `TIMESTAMP_ASC/DESC` direction, or do they remain permanently ascending regardless of the timestamp direction?
