## 2. EvidenceDiscovery Architecture
The `EvidenceDiscovery` component bridges the `DiscoveryCriteria` domain input directly to the three authorized data repositories: `EventRepository`, `ObservationRepository`, and `ReflectionRepository`. It implements the cross-source merge and deterministic order defined by the permanent contract, independently of AI execution.

## 3. Source Selection
The repository queries are strictly bounded by `DiscoveryCriteria.sourceScope`. If the scope is empty, discovery exits early with `0` results without invoking any repository. `LEGACY_AMBIGUOUS` is safely excluded as no repository handles this fallback type.

## 4. Repository Calls
Queries utilize the newly established bounded DAO methods repaired in sprint 11F.2B.3.2:
- `EventRepository.getEventsForTimeWindow`
- `ObservationRepository.getObservationsForTimeWindow`
- `ReflectionRepository.getReflectionsForTimeWindow`

## 5. Time-Range Handling
The `[startTimeMs, endTimeMs)` inclusive-exclusive boundaries are directly enforced in the repository layer and respected by the domain discovery. 

## 6. Filter Handling
- `eventTypes` is safely piped to `EventRepository`. 
- `observationTypes` is safely piped to `ObservationRepository`. If `observationTypes` is empty, it bypasses the repository layer completely to yield 0 results, respecting the domain-contract distinction between `null` (all) and `emptyList` (none). 
- `ReflectionRepository` requires no additional filters per the contract.

## 7. Source-Scope Handling
Only explicitly authorized values within `DiscoveryCriteria.sourceScope` invoke their respective repository.

## 8. Candidate Bounding Strategy
Each repository query is independently bounded by the global `limit`. This fetches at most 3N candidates safely.

## 9. Global Merge Strategy
Candidates from all three sources are pooled into an intermediate `DiscoveryCandidate` data structure representing `(EvidenceReference, timestamp)`. 

## 10. Comparator Implementation
A domain-level `Comparator` strictly implements:
- `timestamp`: Ascending or Descending per `DiscoveryCriteria.ordering`.
- `sourceId`: Ascending as a secondary tie-breaker.
- `sourceType`: Ascending according to the canonical map as a tertiary tie-breaker.

## 11. sourceType Mapping
The explicit canonical map used in the comparator:
```kotlin
val sourceTypeOrder = mapOf(
    EvidenceSourceType.EVENT to 0,
    EvidenceSourceType.OBSERVATION to 1,
    EvidenceSourceType.REFLECTION to 2,
    EvidenceSourceType.LEGACY_AMBIGUOUS to 3 // Safe fallback
)
```

## 12. Deduplication Strategy
After sorting, candidate `EvidenceReference`s are passed through `distinct()`, which safely preserves the first deterministic occurrence of a given `(sourceType, sourceId)` pair.

## 13. Global-Limit Strategy
The globally merged, deterministically sorted, and deduplicated sequence is finally truncated via `.take(limit)`, strictly enforcing the overall bounded limit requested.

## 14. Error Semantics
Failure from any underlying repository query immediately returns a `Result.Failure`, halting the pipeline and propagating the domain error natively. Zero matches returns a successful `Result.Success(emptyList())`.

## 15. Privacy/Logging Behavior
Evidence raw payloads, reflection contents, and precise locations never enter the EvidenceDiscovery payload or its logging loop.
