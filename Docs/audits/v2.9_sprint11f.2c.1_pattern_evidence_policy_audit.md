# V2.9 Sprint 11F.2C.1 Pattern Evidence Policy Audit
**Status:** PATTERN EVIDENCE POLICY BLOCKED — PRODUCT/DOMAIN DECISIONS REQUIRED

## 1. Existing Pattern Semantics
In the current implementation, a `Pattern` represents an authoritative, domain-owned behavioral construct derived from durable evidence. However, **pattern creation is not yet implemented.** The system currently only proposes AI-generated `PatternCandidate` objects, which are strictly logged and NOT persisted.

## 2. Existing Pattern Creation Flow
There is currently **NO** domain logic to create a `Pattern` from a `PatternCandidate`. Use cases such as `LearnInterventionResponsePatternUseCase` and `LearnInterventionTimingPatternUseCase` fetch data, request an AI hypothesis, log the resulting `PatternCandidate`, and explicitly state: *"DO NOT directly persist these candidates. The future Pattern Engine will validate evidence, calculate confidence, and manage state."*

## 3. Existing Confidence Flow
Confidence is currently only modified in one place: `PatternEngineImpl.decayStalePatterns()`. There is no implementation dictating how the initial confidence of a `Pattern` is calculated upon creation. Initial confidence assignment remains a complete contract gap.

## 4. Existing Decay Flow
Decay is explicitly implemented in `PatternEngineImpl.decayStalePatterns()`:
- It checks patterns where `status == ACTIVE`.
- If `now - pattern.lastObservedAt > DECAY_THRESHOLD_MS` (30 days), confidence is decayed.
- Decay formula: `newConfidence = confidence * 0.5f`.
- If `newConfidence < 0.1f`, the pattern status changes to `EXPIRED`.
- *Conclusion:* Decay reduces confidence and eventually expires patterns; it does not retroactively invalidate the original evidence.

## 5. Existing Contradiction Flow
The AI populates `PatternCandidate.contradictionSignal` with its hypothesis. However, existing tests (`PatternCandidateBoundaryTest`) and architecture explicitly mandate: *"The contradictionSignal must NOT automatically mutate or expire a Pattern."* Contradiction is currently an inert AI hypothesis without domain resolution logic.

## 6. Existing User-Correction Flow
While `Memory` has implemented confirmation flows (`ConfirmMemoryUseCase`, `CorrectMemoryUseCase`), `Pattern` does not. Although `Pattern` possesses a `MemoryConfirmationState` field, there are no use cases that allow a user to confirm, correct, or reject a Pattern.

## 7. Existing Evidence Behavior
Evidence is strictly identified by `EvidenceReference(sourceId, sourceType)`. Deduplication via identity is supported, preventing raw string analysis.

## 8. Existing Temporal Behavior
**NO EXISTING TEMPORAL POLICY FOUND.** There are no rules indicating whether evidence must span distinct days or if a cluster of identical timestamps is sufficient to form a Pattern.

## 9. Existing Source-Diversity Behavior
**NO EXISTING SOURCE-DIVERSITY POLICY FOUND.** There is no logic differentiating a pattern formed solely from `EVENT`s versus a mixed-source pattern (e.g., `EVENT` + `REFLECTION`).

## 10. Existing Numeric Policies
The only authoritative numeric constants relating to Patterns reside in `PatternEngineImpl`:
- `DECAY_THRESHOLD_MS`: 30 days (`30L * 24L * 60L * 60L * 1000L`)
- `DECAY_FACTOR`: 0.5f
- `EXPIRATION_CONFIDENCE_THRESHOLD`: 0.1f
There are **zero** numeric constants for pattern creation, minimum evidence, or observations required.

## 12. Evidence Sufficiency Implications
Because there are zero numeric thresholds for creation, Evidence Sufficiency cannot currently be implemented as a deterministic domain function. We cannot hardcode ">= 3" without violating the requirement to avoid inventing arbitrary product rules.

## 13. Contract Gaps That Genuinely Require Decisions
1. **Creation Threshold:** How many unique `EvidenceReference`s are strictly required to instantiate a Pattern?
2. **Temporal Spread:** Must the evidence span a minimum time delta (e.g., > 24 hours)?
3. **Confidence Calculation:** How does the domain calculate the initial `confidence` float from the evidence set?

## 14. Rules That Must NOT Be Invented
- Do not invent arbitrary evidence counts (e.g., "3 events").
- Do not invent time windows for sufficiency.
- Do not invent confidence formulas based on AI probabilities.

## 15. Recommended Next Contract Decisions
Before Sprint 11F.2C can proceed, the Product/Architecture layer MUST define:
1. `minEvidenceCount` for Pattern creation.
2. `minTemporalSpan` (if any) to prevent single-event clusters from becoming Patterns.
3. An explicit formula for initial Pattern Confidence.
