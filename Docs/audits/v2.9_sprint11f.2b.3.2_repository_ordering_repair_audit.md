# V2.9 Sprint 11F.2B.3.2 Repository Ordering Repair Audit

## 1. Previous Contradiction
The existing bounded time-window queries implemented in the DAO layer (e.g., `IronMindDao.kt`, `ObservationDao.kt`) used `ORDER BY timestamp DESC, id DESC` for descending sorts. This directly contradicted the permanent ordering contract, which specifies that the secondary tie-breaker (`sourceId` which corresponds to `id`) must ALWAYS remain ascending, regardless of the primary timestamp direction.

## 2. Affected DAO Methods
The following methods and queries were repaired:
- `IronMindDao.getReflectionsForDateRangeDesc`
- `IronMindDao.getEventsForDateRangeDesc`
- `IronMindDao.getEventsForDateRangeWithTypesDesc`
- `ObservationDao.getObservationsForTimeWindowDesc`
- `ObservationDao.getObservationsForTimeWindowWithTypesDesc`

Additionally, the fake DAO in `ObservationRepositoryImplTest` contained a sorting mechanism using `thenByDescending { it.id }` which was updated to `thenBy { it.id }`.

## 3. Exact Ordering Before Repair
- `ORDER BY createdAt DESC, id DESC LIMIT :limit`
- `ORDER BY occurredAt DESC, id DESC LIMIT :limit`

## 4. Exact Ordering After Repair
- `ORDER BY createdAt DESC, id ASC LIMIT :limit`
- `ORDER BY occurredAt DESC, id ASC LIMIT :limit`

## 5. ASC Behavior
- Time queries mapping to `TIMESTAMP_ASC` use `ORDER BY <timestamp> ASC, id ASC`.

## 6. DESC Behavior
- Time queries mapping to `TIMESTAMP_DESC` use `ORDER BY <timestamp> DESC, id ASC`.

## 7. Same-Timestamp Tie Behavior
With the repair, if multiple records share the exact same timestamp, their deterministic order is decided by `id ASC` (alphanumerical/UUID ascending). This holds true regardless of whether the primary temporal search is ascending or descending.

## 8. LIMIT Behavior
Because the correct tie-breaker is applied natively within the database query, the final limit truncation occurs deterministically on the correct sequence of records. In a descending scenario, the "earliest" IDs among matching timestamps will correctly push out "later" IDs if they span the boundary.

## 9. [start,end) Verification

## 11. Type-Filter Verification
