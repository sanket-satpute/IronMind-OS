## 2. Evaluator Contract
`EvidenceSufficiencyEvaluator` was built as a pure, deterministic domain function. It accepts a list of `ValidatedEvidence` (which pairs an `EvidenceReference` with an authoritative timestamp in milliseconds) and a `ZoneId` for the evaluation timezone. It does not interface with any repositories, AI models, or global state.

## 3. Algorithm
The algorithm deterministically follows the V1 policy:
1. Deduplicates the inputted evidence based on `EvidenceReference` identity (sourceId, sourceType).
2. Checks if the unique evidence count is >= 3. If not, returns `INSUFFICIENT(INSUFFICIENT_UNIQUE_EVIDENCE)`.
3. Converts the remaining evidence timestamps to `ZonedDateTime` at the domain-supplied `ZoneId` and truncates to `DAYS` to find distinct calendar days.
4. Checks if the distinct calendar days count is >= 2. If not, returns `INSUFFICIENT(INSUFFICIENT_DISTINCT_CALENDAR_DAYS)`.
5. Returns `SUFFICIENT` if both criteria pass.
6. Traps arbitrary exceptions into an `ERROR` state.

## 4. Result Contract
Results are encapsulated in the `EvidenceSufficiencyResult` sealed class:
- `Sufficient`
- `Insufficient(val reason: EvidenceSufficiencyReason)`
- `Error(val exception: Throwable)`

Reasons are mapped in the `EvidenceSufficiencyReason` enum, cleanly distinguishing why the sufficiency failed.

## 5. Privacy Behavior
The evaluator respects the strict privacy boundary. It takes only the identity and timestamp of the evidence. When logging, it outputs only structural metadata required by the lifecycle contract:
`IronMindLifecycle [EvidenceSufficiency] [EVALUATED] uniqueEvidenceCount=... distinctCalendarDays=... result=...`
No payload text, reasoning prose, or locations are ever parsed or logged.
